# Save Image with Provenance

## ノードの役割と機能

**Save Image with Provenance** は、Save Image と同様に生成画像を PNG として保存し、生成情報を各 PNG に埋め込む出力ノードです。上流の生成グラフ、利用可能な場合は編集用ワークフロー、生成条件の読みやすい説明、対応画像ローダーが使用した元ファイルを記録します。画像と生成情報をひとつのファイルにまとめられます。

## ComfyUI に追加して使う

1. `__init__.py` を含む `comfyui_png_provenance` フォルダーを、ComfyUI のインストール先にある `custom_nodes` フォルダーへコピーします。配置後のパスが `ComfyUI\custom_nodes\comfyui_png_provenance\__init__.py` になるようにしてください。
2. ComfyUI を再起動し、ブラウザーを再読み込みしてフロントエンド拡張も読み込みます。ブラウザーの再読み込みだけでは、新しいカスタムノードは読み込まれません。
3. ワークフローの最後にある Save Image ノードを **Save Image with Provenance** に置き換えます。最終段の `IMAGE` 出力を `images` に接続し、`filename_prefix` を設定してワークフローを実行してください。

ノードが表示されない場合は、ComfyUI の起動ログでカスタムノードの読み込みエラーを確認してください。`--disable-metadata` を指定している場合は、解除してから使用してください。

バッチ内の各画像を含め、出力は通常の PNG です。サイドカーファイル、ネットワークリクエスト、モデルのダウンロードは発生せず、標準の保存動作にも変更はありません。

## 出力ピンとEagleへの接続

保存とプレビューは従来どおりです。次の3ピンから、バッチ内の画像ごとに対応した順序でリスト出力します。

| 出力 | 型と内容 | Send Image to Eagleの接続先 |
|---|---|---|
| `PNG data` (`png_data`) | `PNG_DATA`: 入力画像とメタデータを内包した保存PNGそのもののバイト列 | `png_data` |
| `filename` | `STRING`: 拡張子・連番を含む保存ファイル名 | `name` |
| `Description` (`description`) | `STRING`: PNGに記録したDescriptionと同じ文字列 | `annotation` |

`custom_nodes\comfyui_to_eagle` も配置・更新し、ComfyUIを再起動してブラウザーを再読み込みしてください。**Send Image to Eagle** の `name` と `annotation` を入力ソケットに変換して、上記の3ピンを接続します。ComfyUIの標準リスト処理でバッチ全件を画像ごとに送信します。PNG入力は `images` より優先し、再エンコードしないため生成情報を保持します。送信後もoutputの保存ファイルは残ります。

`PNG_DATA` は通常の `IMAGE` テンソルとは異なります。送信ノードに通常のIMAGEを接続すると、生成情報のない別のPNGを作成します。入力画像を含むPNG全体がノード出力として実行キャッシュに保持される間、その分のメモリを使用します。

## 記録される内容

- `prompt`: 保存ノードと、そこに接続された上流の生成グラフ。
- `workflow`: 渡された場合は、ComfyUI に PNG をドラッグ＆ドロップして通常どおり読み込める編集用ワークフロー。これは**フィルタリングされていない復元用データ**であり、解析には使用しないでください。
- `Description`: 生成条件と入力ファイル一覧を、人が読める形式で記録します。日本語のプロンプトを含む Unicode 文字を保持します。この項目の表示対応はビューワによって異なります。別のEagle送信ノードの `annotation` にも渡せます。
- 標準の **LoadImage**、**LoadImageMask**、**LoadImageOutput** が使用した元ファイルのバイト列。保存処理ごとに SHA-256 で重複を除外します。

`prompt` からは、未接続のノードと別の出力分岐が除外されます。接続されていても使われていない遅延分岐は残ることがあります。ノード展開・上書きにより実行時のグラフが送信されたプロンプトと異なる場合は、`runtime_graph` に別途記録します。任意のカスタムローダー、画像以外のアセット、モデルの重み、カスタムノードのコードは収集されません。接続されたファイル名入力はこのノードでは解決できないため、対応ローダーではファイル名を直接指定してください。

**生成中に入力ファイルを変更または削除しないでください。** 保存時に入力ファイルを読み直します。ハッシュは埋め込まれたバイト列の整合性を検証しますが、画像の読み込み時点での内容と同一であることは検証しません。入力ファイルの元のメタデータも保持されるため、PNG を共有する前に埋め込み情報を確認してください。

## フォーマット v1

テキストキーワード `ComfyProvenanceFormat` の値は `comfyui-png-provenance/1` です。`Description` は UTF-8 の iTXt です。`prompt` と `workflow` は標準の JSON テキストフィールドです。

IDAT の後ろにある非公開の ancillary PNG チャンク **cpRV** には、次のデータが格納されます。

| オフセット | 内容 |
|---|---|
| 0 | ASCII の `COMFY-PROVENANCE` に NUL を付加したもの（17 バイト） |
| 17 | ビッグエンディアンの符号なし 16 ビット版番号。現在は 1 |
| 19 | ZIP_STORED 形式の ZIP アーカイブ |

ZIP には UTF-8 の `manifest.json` と、`assets/<sha256>` に配置した元ファイルが含まれます。manifest には `format`、`version`、`graph_scope`、`graph`、`workflow_scope`、`workflow`、`output`、`assets` が含まれます。`runtime_graph` は任意です。各アセットには `entry`、`sha256`、`size`、`extension`、`references` が含まれます。各参照は実行時の `node_id`、取得できる場合は対応する `prompt_node_id`、`class_type`、`input`、元の `filename` を示します。

解析には、フィルタリングされていない `workflow` ではなく **`graph`** を使用してください。`output` は元の保存ノード／実行時の保存ノードと、0 始まりのバッチ位置を示します。モデル、シード、サンプリング設定、テキストはそれぞれ該当するノードの入力として記録されます。すべてのワークフローにサンプラーが一つだけあるとは限りません。

画像の最適化ツール、編集ツール、ビューワは、再保存時に独自メタデータを削除することがあります。復元には生成時の元の PNG を保管してください。

## PNG のドラッグ＆ドロップで復元する

このノードで保存した PNG を、**ComfyUI のキャンバスの空き領域**へドラッグ＆ドロップしてください。内包された入力画像の配置と、保存対象の上流グラフの画面への構築を、一度の操作で行います。`restore.py` の実行、画像のコピー、JSON の読み込みを個別に行う必要はありません。

ドロップするたびに `ComfyUI\input\provenance\restore_<id>\assets` に新しい復元フォルダーを作成します。既存画像の上書きや再利用は行いません。復元画像は、ワークフローで使用できるようディスクに残ります。画面に構築するのは保存対象の上流ノードだけで、配置は再構築されます。フィルタリングされていない編集用ワークフローの原本は読み込みません。対応付けできた LoadImageOutput は、input 内の復元画像を選択できる LoadImage に置き換えます。LoadImageMask のチャンネル設定は保持します。

**生成は自動実行しません。** グラフを確認してから、通常どおりキューへ追加してください。展開済みノード／サブグラフの画像を自動で対応付けできない場合も画像は復元し、元のノードと復元ファイル名を含む警告を表示します。該当箇所は手動で選び直してください。必要なモデルやカスタムノードは引き続き別途用意する必要があります。

通常の PNG は従来どおり読み込まれます。画像ローダーのアップロード領域へのドロップは、ワークフローの復元ではなく従来の画像アップロードとして扱います。不正な生成情報にはエラーを表示し、元のワークフローへ黙って切り替えることはありません。アップロード先はブラウザーが現在接続中の ComfyUI サーバーだけで、既存のアップロードサイズ制限が適用されます。

## 外部ツールからブラウザーへ復元する

フロントエンド拡張は準備が完了した WebSocket 接続を登録し、再接続後も登録し直します。接続・登録済みのブラウザー一覧を取得し、反映先の `client_id` を指定して PNG を送信してください。

```powershell
curl.exe http://127.0.0.1:8188/provenance/clients
curl.exe -X POST http://127.0.0.1:8188/provenance/restore -F "image=@C:\images\generated.png" -F "client_id=反映先のCLIENT_ID"
```

一覧の応答は `{"clients":[{"client_id":"..."}]}` です。復元 API は入力画像を配置した後、指定したブラウザーだけへ `provenance.restored` イベントを送ります。呼び出しごとに新しいワークフロータブへ上流グラフを読み込み、そのタブを表示します。元のタブと未保存の編集は残ります。同名のワークフローがあれば名前に連番を付けます。PNGのドラッグ＆ドロップは従来の置き換え挙動を維持します。ページの再読み込みは不要です。生成は自動実行せず、手動での画像選択が必要な場合は画面に警告を表示します。

成功応答には `notification: {"client_id":"...", "status":"sent"}` が含まれます。これは WebSocket への通知送信までを確認したもので、**画面でのグラフ読み込み完了を保証するものではありません**。グラフの読み込み失敗はブラウザー側で表示します。対象が未接続・未登録の場合は、画像の復元前に 409 を返します。復元中の切断や通知失敗の場合も 409 を返しますが、`error`、復元結果、`directory`、`notification.status = "failed"` を含め、配置済み画像は残します。

`client_id` を省略すると、従来どおり復元結果を応答するだけでブラウザーへ通知しません。通常の PNG ドロップでは `client_id` を送らないため、ワークフローを二重に読み込むことはありません。ブラウザー用の `POST /provenance/clients/register` は `client_id` を含む JSON を受け付けます。外部ツールは通常、一覧と復元のエンドポイントだけを使用します。

client_id と準備完了の登録は**認証の代わりにはなりません**。既存の ComfyUI のアクセス制御の下で、信頼できる呼び出し元からのみ使用してください。無認証の ComfyUI サーバーをインターネットへ公開しないでください。

## ローカル CLI で復元する

CLI は Python 標準ライブラリのみを使用します。torch も、起動中の ComfyUI も必要ありません。

```powershell
python custom_nodes\comfyui_png_provenance\restore.py output\example.png restored
```

PNG チャンクの CRC、フォーマットの版、ZIP の構造、アセットのサイズと SHA-256 ハッシュを検証します。既存のファイルを上書きしたり、メタデータに記録された元のパスへ書き込んだりすることはありません。

出力先には `assets`、`prompt.json`、`references.json` が作成されます。編集用ワークフローが含まれている場合は、`workflow.original.json` と `workflow.json` も作成されます。復元された **`assets` ディレクトリ**を `ComfyUI\input` にコピーしてから、ComfyUI で `workflow.json` を読み込むか、通常の API で `prompt.json` を送信してください。標準ローダーのファイル名は `assets/<sha256>.<extension>` に書き換えられます。元のファイルが output または temp フォルダーから読み込まれた場合も同様です。

編集用ノードに直接対応付けられない展開済みノード／サブグラフの入力は、復元したファイルを手動で選び直す必要があります。CLI は警告を表示し、`references.json` にも記録します。不明なワークフローの編集方法を推測することはありません。入力バンドルは再帰的に展開されません。

編集用ワークフローには、関係のないノードや分岐も残っています。保存した生成分岐だけを再実行する場合は `prompt.json` を使用してください。復元した編集用ワークフローを実行する場合は、キューに追加する前に他の分岐を調整するかどうか確認してください。

モデルファイルとカスタムノードは別途用意してください。乱数、ランタイムのバージョン、デバイス、attention バックエンドが異なると、完全に同じ結果にならない場合があります。ファイルサイズには、元の入力ファイル全体と、そこに含まれるメタデータの分も含まれます。
