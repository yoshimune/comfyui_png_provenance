# Save Image with Provenance

生成条件と入力画像の元ファイルを出力画像に含める場合は、Save Image の代わりに **Save Image with Provenance** を使用してください。最終的な IMAGE を `images` に接続し、`filename_prefix` を設定してワークフローを実行します。このディレクトリを `custom_nodes` に配置した後、ComfyUI を再起動してください。

バッチ内の各画像を含め、出力は通常の PNG です。サイドカーファイル、ネットワークリクエスト、モデルのダウンロードは発生せず、標準の保存動作にも変更はありません。このノードを使用するには `--disable-metadata` を外してください。

## 記録される内容

- `prompt`: 保存ノードと、そこに接続された上流の生成グラフ。
- `workflow`: 渡された場合は、ComfyUI に PNG をドラッグ＆ドロップして通常どおり読み込める編集用ワークフロー。これは**フィルタリングされていない復元用データ**であり、解析には使用しないでください。
- `Description`: 生成条件と入力ファイル一覧を、人が読める形式で記録します。日本語のプロンプトを含む Unicode 文字を保持します。この項目の表示対応はビューワによって異なります。Eagle との連携は含まれません。
- 標準の **LoadImage**、**LoadImageMask**、**LoadImageOutput** が使用した元ファイルのバイト列。保存処理ごとに SHA-256 で重複を除外します。

`prompt` からは、未接続のノードと別の出力分岐が除外されます。接続されていても使われていない遅延分岐は残ることがあります。ノード展開・上書きにより実行時のグラフが送信されたプロンプトと異なる場合は、`runtime_graph` に別途記録します。任意のカスタムローダー、画像以外のアセット、モデルの重み、カスタムノードのコードは収集されません。接続されたファイル名入力はこのノードでは解決できないため、対応ローダーではファイル名を直接指定してください。

**生成中に入力ファイルを変更または削除しないでください。** 保存時に入力ファイルを読み直します。ハッシュは埋め込まれたバイト列の整合性を検証しますが、画像の読み込み時点での内容と同一であることは検証しません。入力ファイルの元のメタデータも保持されるため、PNG を共有する前に埋め込み情報を確認してください。

## フォーマット v1

テキストキーワード `ComfyProvenanceFormat` の値は `comfyui-png-provenance/1` です。`Description` は UTF-8 の iTXt です。`prompt` と `workflow` は標準の JSON テキストフィールドです。

IDAT の後ろにある非公開の ancillary PNG チャンク **cpRV** には、次のデータが格納されます。

| オフセット | 内容 |
|---|---|
| 0 | ASCII の `COMFY-PROVENANCE` に NUL を付加したもの（17 バイト） |
| 17 | ビッグエンディアンの符号なし 16 ビット版番号。現在は 1 |
| 19 | ZIP_STORED 形式の ZIP アーカイブ |

ZIP には UTF-8 の `manifest.json` と、`assets/<sha256>` に配置した元ファイルが含まれます。manifest には `format`、`version`、`graph_scope`、`graph`、`workflow_scope`、`workflow`、`output`、`assets` が含まれます。`runtime_graph` は任意です。各アセットには `entry`、`sha256`、`size`、`extension`、`references` が含まれます。各参照は実行時の `node_id`、取得できる場合は対応する `prompt_node_id`、`class_type`、`input`、元の `filename` を示します。

解析には、フィルタリングされていない `workflow` ではなく **`graph`** を使用してください。`output` は元の保存ノード／実行時の保存ノードと、0 始まりのバッチ位置を示します。モデル、シード、サンプリング設定、テキストはそれぞれ該当するノードの入力として記録されます。すべてのワークフローにサンプラーが一つだけあるとは限りません。

画像の最適化ツール、編集ツール、ビューワは、再保存時に独自メタデータを削除することがあります。復元には生成時の元の PNG を保管してください。

## ローカルで復元する

CLI は Python 標準ライブラリのみを使用します。torch も、起動中の ComfyUI も必要ありません。

```powershell
python custom_nodes\comfyui_png_provenance\restore.py output\example.png restored
```

PNG チャンクの CRC、フォーマットの版、ZIP の構造、アセットのサイズと SHA-256 ハッシュを検証します。既存のファイルを上書きしたり、メタデータに記録された元のパスへ書き込んだりすることはありません。

出力先には `assets`、`prompt.json`、`references.json` が作成されます。編集用ワークフローが含まれている場合は、`workflow.original.json` と `workflow.json` も作成されます。復元された **`assets` ディレクトリ**を `ComfyUI\input` にコピーしてから、ComfyUI で `workflow.json` を読み込むか、通常の API で `prompt.json` を送信してください。標準ローダーのファイル名は `assets/<sha256>.<extension>` に書き換えられます。元のファイルが output または temp フォルダーから読み込まれた場合も同様です。

編集用ノードに直接対応付けられない展開済みノード／サブグラフの入力は、復元したファイルを手動で選び直す必要があります。CLI は警告を表示し、`references.json` にも記録します。不明なワークフローの編集方法を推測することはありません。入力バンドルは再帰的に展開されません。

編集用ワークフローには、関係のないノードや分岐も残っています。保存した生成分岐だけを再実行する場合は `prompt.json` を使用してください。復元した編集用ワークフローを実行する場合は、キューに追加する前に他の分岐を調整するかどうか確認してください。

モデルファイルとカスタムノードは別途用意してください。乱数、ランタイムのバージョン、デバイス、attention バックエンドが異なると、完全に同じ結果にならない場合があります。ファイルサイズには、元の入力ファイル全体と、そこに含まれるメタデータの分も含まれます。
